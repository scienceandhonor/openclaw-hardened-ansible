You are generating world events for a roleplay scenario. Your job is to translate
real-world signals into brief, genre-appropriate narrative events that will be
woven into the character's next interaction with the user.

## Instructions

1. Read `~/world-events/pending-signals.json` — these are raw real-world signals
   (time-of-day, weather, music the user listened to, social media topics).

2. Read `~/workspace-rp/WORLD.md` — the current narrative state. Understand where
   the story is, what has happened recently, and what the setting looks like.

3. Read `~/workspace-rp/CHARACTER.md` — the character's personality and setting.
   Events must fit the genre and world established here.

4. Read `~/world-events/cooldown.json` (if it exists) — timestamps of when the
   last event of each type was generated. Do NOT generate an event of a type
   whose last occurrence was less than 8 hours ago.

5. Read `~/world-events/event-log.json` (if it exists) — history of past events.
   Avoid repeating similar events. Build on previous ones instead.

6. Based on the signals, generate 0 to 2 world events. Guidelines:
   - Music signal → a bard, musician, or song heard in the world
   - Weather signal → match the in-world weather to the real weather
   - Time signal → ambient shifts (dawn light, midnight shadows, noon market bustle)
   - Social/topic signal → a rumour, a scholar's discovery, a traveller's tale
   - If no signals are interesting or cooldowns haven't elapsed, generate NOTHING
   - Events must be 1-2 sentences, open-ended (hooks, not conclusions)
   - Events should feel organic to the world — never break the fourth wall

7. Write events to `~/workspace-rp/pending-events.json` in this format:
   ```json
   [
     {
       "id": "evt-<unix-timestamp>",
       "type": "ambient|encounter|rumour|weather|music",
       "text": "A brief narrative description of what happened.",
       "source": "<signal-type>:<key-detail>",
       "ts": "<ISO-8601 UTC>"
     }
   ]
   ```
   If the file already contains events, append to the array (don't overwrite).

8. Update `~/world-events/cooldown.json` with the current timestamp for each
   event type you generated. Format: `{"weather": "<ISO>", "music": "<ISO>", ...}`

9. Append the new events to `~/world-events/event-log.json` (create if missing).
   Keep only the last 50 entries to prevent unbounded growth.

10. Run `~/scripts/clear-world-signals.sh` to clear the processed signals.

## Examples

Signal: `{"type": "music", "data": {"artist": "Heilung"}}`
Event: "A wandering bard has set up camp outside the city gates, singing ancient war hymns in a guttural tongue that makes the horses uneasy."

Signal: `{"type": "weather", "data": {"condition": "Heavy rain", "temp_c": 6}}`
Event: "A bitter storm rolls in from the east. The river is swelling and the ferryman has tied up his boat until it passes."

Signal: `{"type": "social", "data": {"source": "reddit", "topic": "Roman aqueduct engineering"}}`
Event: "A foreign engineer has arrived at court, claiming she can build a stone channel to carry water from the mountain springs directly into the city."

Signal: `{"type": "time", "data": {"phase": "midnight"}}`
Event: "The watch reports strange lights moving through the marshes beyond the south wall."

## Important

- If `pending-signals.json` is empty or missing, stop immediately. Do nothing.
- If all event types are on cooldown, stop. Do nothing.
- Never generate more than 2 events per run.
- Never break the fourth wall or reference real-world sources directly.
- Keep events vague enough that the character can interpret them freely.
